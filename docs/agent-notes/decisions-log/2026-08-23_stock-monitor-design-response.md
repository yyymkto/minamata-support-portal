# [2026-08-23] ストック情報監視スクリプトの設計確定・実装（Antigravity提案への回答）

**決めた人/エージェント**: Claude（Antigravityからの相談 `2026-08-23_stock-monitor-proposal.md` への回答として）
**関係者**: Antigravity、Claude、吉野さん

## 背景・課題

Antigravityより、`child_support_base.json` に登録された制度URLのサイレント更新
（新着情報に載らない内容変更）を検知する監視スクリプトの提案があった
（`decisions-log/2026-08-23_stock-monitor-proposal.md`）。
提案では「404検知」「最終更新日の変化」「本文ハッシュの差分」のどれを採用するか、
実装の最適解をClaude側に相談したいとのことだった。

## 調査で分かったこと

WebFetchで水俣市サイトの実ページ（`kiji003155/index.html`、児童手当）のHTMLを直接確認したところ、
記事ページ本文の冒頭に以下の構造化マークアップが存在することが判明した。

```html
<div class="updDate">最終更新日：<time datetime="2024-11-28T16:44:12+09:00">2024年11月28日</time></div>
```

`<time datetime="...">` のdatetime属性はISO 8601形式で機械可読であり、
可視テキストの正規表現抽出より確実に日付を取得できる。
`child_support_base.json` に記録されている全27件の `official_url` に対して実際に
このセレクタで日付抽出を試したところ、既存の `last_verified` の値と完全に一致した
（例: child-medical-subsidy → 2026-07-17、child-rearing-allowance → 2026-07-24 等）。
これにより、過去のエージェントが手作業で確認していた「ページの最終更新日」は、
このマークアップから機械的に取得可能であることが実証された。

なお `medical-care-child-guideline`（水俣市医療的ケア児に関するガイドライン）は
過去の調査で「ページ自体の最終更新日が未確認」と記録されていたが、今回の調査で
実際には `2026-08-10` の更新日マークアップが存在することを確認した
（次のデータ更新時に反映を推奨）。

また、水俣市サイトはHTTPレスポンスヘッダーでcharsetを明示していないため、
`requests` ライブラリが仕様上のデフォルトである `ISO-8859-1` と誤判定し、
日本語本文が文字化けする問題があった。`resp.apparent_encoding` で上書きする対応を入れた。

## 決定内容

1. **主たる検知方式は「`<time datetime>` 属性からの最終更新日抽出」を採用**。
   `last_verified` より新しい日付が見つかった場合を「更新の可能性あり」として報告する。
   本文ハッシュより誤検知が少なく、日付という意味のある差分を直接得られるため。
2. 可視テキストの正規表現（「最終更新日：YYYY年MM月DD日」）は、テンプレートが
   異なるページに備えたフォールバックとして残す。
3. **本文ハッシュ比較は、日付マークアップが見つからないページのみのフォールバック**として採用。
   ヘッダー・フッター・ナビゲーションを除去してから比較することで、サイト共通レイアウトの
   変更による全ページ誤検知は防ぐが、それでも誤検知は本質的に残るため、Issue本文で
   「要目視確認」と明記し、対応不要なら閉じてよい旨を案内する。
4. **404（リンク切れ）は最優先で報告**する独立カテゴリとする。
5. スクリプトは `child_support_base.json` を**自動更新しない**。検知結果はMarkdownレポート
   としてGitHub Issueに起票するのみとし、実データの更新は人間またはエージェントが
   内容を確認した上で手動で行う（静的データの手動メンテナンス方針を維持するため）。
6. 週次実行は `update_data.py`（毎朝7:00 JST）と時間帯をずらし、
   毎週月曜8:00 JSTとした（cron: `0 23 * * 0`）。
7. ハッシュ比較用の状態（前回実行時の日付・ハッシュ）は `public/data/_monitor_state.json`
   に保存し、CIワークフロー内で `life_info.json` と同様の自動コミット方式で永続化する。

## 却下した選択肢

- **本文ハッシュ比較のみで検知**（提案の選択肢の一つ）: サイト共通レイアウトの変更や
  広告・お知らせバナー等の変化にも反応し、Issueが頻発して形骸化するリスクがあるため、
  日付マークアップが取得できる限りは使わない方針にした。
- **`update_data.py` に統合**: Antigravityの提案時点で既に却下済み（フロー/ストック混在の懸念）。
  今回の実装でも独立スクリプト・独立ワークフローとした。
