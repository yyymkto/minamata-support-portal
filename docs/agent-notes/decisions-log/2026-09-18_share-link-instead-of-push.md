# [2026-09-18] LINEプッシュ通知ではなく、制度カードの共有リンクを先に作る

**決めた人/エージェント**: 吉野さん（Claude Codeの整理を受けて）
**関係者**: 吉野さん、Claude Code

## 背景・課題

子育て支援制度タブの改装が本番に反映された後、吉野さんから
「希望する人にLINEなどでプッシュ通知する仕組みは大変か」という相談があった。

Claude Codeが実現方式を調べたところ、最も軽い形（LINE公式アカウントを作り、
GitHub Actionsから週1回まとめて一斉送信する）なら実装自体は1日程度で済む。
一方で、受け取る分野を選べるようにすると、登録者の情報を保存する常時稼働の
サーバーが必要になり、「サーバーを持たない静的サイト」という現在の構成から
大きく外れることが分かった。

これを受けて吉野さんから「そこまでするのではなく、共有リンクを送れる仕様を
つけるほうが良いのでは」という提案があり、検討した。

## 決定内容

- **プッシュ通知は当面見送り、制度カードごとの共有リンクを先に作る。**
  設計書は `design-specs/2026-09-18_share-link.md`。
- 共有の単位は**制度カードごと**とする（カテゴリ単位は作らない）。
- 共有ボタンだけでなく、**受け取ったリンクが正しく開くこと**を主眼とする。
  現在はサイトを開くと必ずフィードタブが表示されるため、`#base-...` 付きの
  URLを送っても受け取った人にはその制度が見えない。
- LINEで送ったときのプレビューは、サイト全体の文言（OGP）までとする。
  制度ごとの見出しを出すにはHTMLを制度の数だけ生成するビルドステップが必要で、
  「ビルドステップなし」という構成を変えることになるため。

判断の理由は、制度情報が毎日変わるものではなく、「妊娠がわかった」
「小学校に上がる」など**その人に必要になった時に読むもの**であること。
継続的に押し出すより、知っている人が必要な人に渡せる形のほうが情報の性質に合う。

## 却下した選択肢（あれば）

- **LINE公式アカウントで週1回の一斉配信** → 実装は軽いが、アカウントの運用、
  費用（無料枠は月200通。「送信回数×友だち数」で数えるため、週1回なら
  友だち45人程度で上限に達し、以降は月5,000円のプランが必要）、
  配信内容の事前確認（AIが自動生成した要約は、サイトなら直せるが
  送信済みメッセージは取り消せない）が継続的に発生する。
  また市は既に公式LINE（`@minamata-city`）を運用しており、非公式サイトが
  並行して通知を送るなら、市の配信との違いを説明できる必要がある。
- **分野を選べるプッシュ通知** → 登録者ごとの選択を保存するサーバーと
  個人情報の扱いの整理が必要。静的サイトという構成から外れるため見送り。
- **ブラウザのWeb Push通知** → 同じくサーバーが必要で、iPhoneでは
  ホーム画面に追加した人にしか届かない。
- **カテゴリ単位の共有** → 「この制度を教えたい」が主な使われ方と考えられ、
  入口を増やすと主役である制度への導線が弱くなる。

将来プッシュ通知を再検討する場合、この決定は「やらない」ではなく
「共有リンクを先にやる」であり、利用状況を見てから改めて判断する。
