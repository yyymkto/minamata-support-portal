# [2026-10-07] イベントに申し込み情報（要申込・締切・受付終了・締切が近いもの）を出す

**決めた人/エージェント**: 吉野さん（Claude Codeが出した候補から選択）
**関係者**: 吉野さん、Claude Code

## 背景・課題

吉野さんから「申し込みが必要なイベントについて手を加えたいが、どうするのが良いか発想がない」と相談があった。
Claude Codeが掲載中の15件の元ページを確認したところ、申し込みかチケットが必要なものが5件、
一部だけ申し込み制のものが1件あった。しかしカードに申し込みの情報は出ておらず、
一覧が開催日順のため、開催日より前にある締切に気づきにくい（例：sunset YOGA 開催10/10・締切10/8）。
吉野さんも「開催日順だと埋もれがち」と感じていた。

## 決定内容

設計書は `design-specs/2026-10-07_event-registration.md`。

- 候補5案（A：カードに要申込・締切・方法／B：締切後は受付終了／C：締切が近いものを上部にまとめる／
  D：申込不要で絞り込み／E：締切をカレンダーに登録）のうち、**A＋B＋C** を採用。
- 一覧そのものは開催日順のまま。締切が14日以内のものだけを上部に締切順で1行ずつまとめる。
- 「申込不要」は記事にそう書いてあるときだけ。推測で付けない。
- 自動抽出ではAIの判定を記事本文の言葉で確かめる（実装時に追加。AIが本文に無い文を作って「申込不要」にした例があったため）。
- 「受付終了」は画面側で締切日と今日の日付から判定する。定員到達による受付終了は扱わない。
- シート1と投稿フォームに「申込」「申込締切」「申込方法」の3列を足す（任意列。フォームの「申込」は必須の質問）。
- 急かす言い回し（「お早めに」「あと2日」等）は使わない（2026-08-26の方針）。

## 却下した選択肢（あれば）

- **D. 申込不要で絞り込むボタン**：判定できないイベントが多く、絞り込むと結果が少なくなりすぎる。Aのデータが貯まってから再検討。
- **E. 締切をカレンダーに登録するボタン**：Aができた後の追加機能。今回は見送り。
- **一覧全体を締切順に並べる**：締切の無いイベント（祭り・マルシェ等）の置き場所が無くなる。
- **開催前のイベントの元ページを毎日読み直し、定員到達による受付終了を拾う**：
  市のサイトへのアクセスとGeminiの呼び出しが毎日増える。必要になったら別途設計する。
