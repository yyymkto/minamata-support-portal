# [2026-08-23] [提案] 静的データ（ストック情報）の自動監視スクリプトの設計

**提案者/エージェント**: Antigravity
**確認・レビュー依頼先**: Claude, 吉野さん

## 背景・課題

市のサイトでは、各カテゴリごとの静的な一覧ページ（例：`list00301.html`）が存在し、子育て支援制度などの「ストック情報」が新着情報（フロー）には載らずにサイレント更新される可能性がある。
これらを既存の `update_data.py`（新着情報の収集スクリプト）に含めてしまうと、恒久的な制度情報が日々の「お知らせフィード」に大量に混入し、本来の「フローとストックの分離」というサイトコンセプトが破綻してしまう。

## 提案内容（Claudeへのレビュー依頼）

動的データの収集（`life_info.json`）とは完全に独立した、「静的データの監視専用ワークフロー」の構築を提案する。

1. **監視対象**: `child_support_base.json` などに登録済みの制度URL（`official_url`）。
2. **実行基盤**: GitHub Actions（例：`.github/workflows/weekly-monitor.yml`）で週1回等の定期実行。
3. **スクリプト**: 新規スクリプト（例：`scripts/monitor_stock.py`）を作成。
4. **処理フロー（想定）**:
   - JSON内のURLリストをループしてアクセス。
   - 404エラー（リンク切れ）や、ページ内の「最終更新日」の変更、あるいはメインコンテンツのハッシュ値の差分を検知する（ここはClaudeに実装の最適解を相談したい）。
   - 差分やエラーを検知した場合、GitHub APIを通じて自動でIssueを起票。「〇〇の制度ページに更新がありました。内容を確認して JSON を手動更新してください」と人間（またはエージェント）に通知する。

## 却下した選択肢

- **既存の `update_data.py` でカテゴリページを巡回し `life_info.json` に混ぜる案**: 
  - 理由：ストック情報がフロー情報に混在し、最新の重要なお知らせが埋もれてしまう。また、更新日の取得が難しいカテゴリページを毎日巡回させると、毎回「新着」としてGemini APIに送られ、コストが無駄にかかるため却下。

## 影響を受ける（追加する）ファイル

- `scripts/monitor_stock.py` (新規)
- `.github/workflows/weekly-monitor.yml` (新規)
