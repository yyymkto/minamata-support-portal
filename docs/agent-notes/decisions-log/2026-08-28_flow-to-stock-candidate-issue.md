# [2026-08-28] 「最新のお知らせ」からストック制度候補を検出し、Issueで通知する機能

**決めた人/エージェント**: 吉野さん（Claudeとの壁打ちを経て）
**関係者**: 吉野さん、Claude

## 背景・課題

「最新のお知らせ」（フロー、`life_info.json`）の中に、恒常的な制度としてストック側
（`child_support_base.json`・`young_adult_support_base.json`）に載せる価値がある
情報が紛れていても、今は誰も気づく仕組みがない。

似た発想の機能（ストック側に「関連する最新のお知らせ」を表示）は2026-08-27に
削除済み。世代・ジャンルタグという緩い一致だけで紐付けていたため精度が粗く、
「あまりピンと来ない」結果になったことが原因だった。今回は逆方向（フロー→ストック）
だが、同じ精度問題を繰り返さないための設計が必要だった。

## 決定内容

- **自動書き込みはしない**。該当しそうな記事があれば**Issueで通知するのみ**とし、
  最終判断・データ反映は人（吉野さん）が行う
  - 検討時に「(a)既存ストック項目の更新のみ自動化／(b)新規候補はIssue止まり」という
    案も出たが、吉野さんの「常設の制度が増えることはあまりない＝自動書き込みの
    複雑さに見合わない」との判断で、(a)(b)問わず**全てIssue通知のみ**に一本化した。
    これにより「PRにするか直接pushか」という論点自体も不要になった。
- **判定基準**：既存ストック一覧（現時点27+9件）を判定材料としてGeminiに渡し、
  対象記事が「特定の1件を指しているか（更新情報）」または「一覧にない、恒常的な
  制度・給付・窓口の新設らしいか」を判定する。
  期間限定のキャンペーン・イベント・募集は対象外とする
  （`child_support_base.json`の`permanence=time_limited`の考え方と揃える）。
- **頻度**：毎日ではなく、`weekly-monitor.yml`と同じ週1回（毎週月曜8:00 JST）。
  直近1週間分の`life_info.json`新規項目のみを対象にする。
  - 実データ確認（初回一括収集を除く定常運用）：新規項目は1日あたり2件程度、
    週換算で10〜15件程度。RPD500・RPM15に対して十分小さいことを確認済み。
- **通知形式**：既存の`stock-update-detected-issue.md`と同じパターンでIssue起票
  （該当が複数件あれば1つのIssueにまとめる）。

## 却下した選択肢

- ストックデータへの自動書き込み（直接push or PR）：前回削除した機能と同種の
  精度事故リスクがあり、常設制度の追加頻度自体が低いため費用対効果が低いと判断
- 毎日判定：新規制度の発見に緊急性はなく、週次で十分。API消費も抑えられる

## 影響を受けるファイル（実装予定）

- `scripts/update_data.py` または新規スクリプト：週次でストック候補を判定する処理
- `.github/workflows/weekly-monitor.yml`：ストック候補判定ジョブの追加
- `.github/workflow-templates/`：ストック候補検出用のIssueテンプレート新規作成
