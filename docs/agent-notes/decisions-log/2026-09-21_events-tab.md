# [2026-09-21] イベントタブを新設し、SNSは自動収集せず手動登録で補う

**決めた人/エージェント**: 吉野さん（Claude Codeの整理を受けて）
**関係者**: 吉野さん、Claude Code、Antigravity

## 背景・課題

吉野さんから「水俣市内で開催予定のイベント（お祭り・マルシェ等）を可視化したい。
使うのは水俣市民や、観光などで来る市外の人。SNSから拾い上げて掲載する形を考えている」
という相談があった。

Claude Codeが確認したところ、次のことが分かった。

- Instagram・Facebook・Xは規約で自動収集（スクレイピング）を禁止しており、
  他人の投稿を検索できるAPIも実質使えない（Xは有料）。GitHub Actionsで巡回する方式は取れない。
- 一方で、既存の自動収集（`life_info.json`）には「イベント」タグの記事がすでに46件あり、
  足りないのは開催日・場所の項目だけだった。記事ページの本文にはそれらが書かれている。
- 吉野さんが挙げたInstagram（`@minamata_kanko_`）は、すでに自動収集している
  観光物産協会（go-minamata.jp）のアカウントとみられる。

## 決定内容

- 「イベント」タブを新設し、開催日が近い順の一覧で表示する（カレンダー表示ではなく一覧）。
- 「一人暮らし・若者支援」タブは一時的に非表示にし、その位置にイベントタブを置く（フラグでオフにし、コード・データは残す）。
- 自動：既存の収集記事からGeminiで開催日・場所等を読み取り、**確認なしでそのまま掲載する**。
  代わりに注意書きと元ページへのリンクを必ず付け、日付を読み取れなかった記事は載せない。
- 手動：SNSでしか告知されないイベントは、吉野さんが**Googleスプレッドシート**に登録する（週1時間以内）。
  同じシートで、自動抽出分の修正（上書き）や非表示もできるようにする。

詳細は `design-specs/2026-09-21_events-tab.md`。

## 検討した他の案

- SNSの自動収集：規約・APIの制約で不可。
- 主催者からの投稿フォーム：周知と確認の手間がかかるため、v1では入れない。反応を見て検討する。
- 手動登録の方法として「Claude Codeに頼んでpushしてもらう」「GitHub上でJSONを直接編集する」も挙げたが、
  スマホから行を足すだけで済むスプレッドシートを吉野さんが選んだ。
- 自動抽出分を吉野さんが確認してから掲載する案：週1時間を手動登録に回すため見送った。
