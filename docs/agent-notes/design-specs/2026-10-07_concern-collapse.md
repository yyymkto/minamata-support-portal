## 概要

子育て支援制度タブの制度が40件になった（2026-10-07、基幹相談支援センター「キャンバス」を追加）。
改装の設計書（`2026-09-16_child-support-page-renovation.md`「なぜ折りたたみ・検索を今回入れないか」）で
「40件を超えたあたりで折りたたみか検索が必要」としていた目安に達したため、吉野さんの判断で**折りたたみ**を入れる。

**困りごと（20個）ごとに、制度カードを閉じた状態で表示する。** 開くと今と同じカードが出る。
困りごとの見出しと件数、中の制度名は閉じたままでも読めるようにし、
2026-08-15に決めた「タップしなくても何があるか見渡せる一覧」（`decisions-log/2026-08-15_stock-view-no-click.md`）の良さを残す。

現在の構成（2026-10-07）：カテゴリ4つ → 困りごと20個 → 制度カード45枚（同じ制度が複数の困りごとに出るため、制度は40件）。

## データ構造

## 画面仕様

対象は `src/index.html` の `concernSectionHTML` と `renderConcernSet`（[index.html:1071-1145](../../../src/index.html#L1071-L1145)）。
同じ関数を使っている「一人暮らし・若者支援」タブ（現在は非表示）にも同じ見た目が入るが、それでよい。

### 1. 困りごとの見出し（閉じた状態）

```
特別なサポート                                         17件
─────────────────────────────────
┃ ひとり親家庭向けの支援を知りたい                   7件  ⌄
┃ 児童扶養手当・ひとり親家庭等医療費助成・母子父子寡婦福祉資金…
─────────────────────────────────
┃ 障がいのある子ども向けの支援を知りたい             4件  ⌄
┃ 特別児童扶養手当・小児慢性特定疾病児童日常生活用具給付・…
─────────────────────────────────
```

- `<details>` と `<summary>` で作る（ブラウザ標準の開閉。キーボード操作・読み上げにそのまま対応する）。
  `<summary>` の中に今の `<h3>`（`font-serif font-medium text-[15px] border-l-2 border-bay/40 pl-3`）を入れる。
- 見出しの右に件数（その困りごとで今表示される制度の数。絞り込み後の数）と、開閉の印（下向きの山形、開いたら上向き）を置く。
  件数は `text-xs text-inkSoft tabular`。
- 見出しの下に、**中の制度名を「・」でつないだ1行**（`text-xs text-inkSoft`、はみ出す分は「…」で省略）。
  開いているときはこの行を出さない（下にカードが出るため）。
- 標準の三角印は消す（`summary { list-style: none }`、`summary::-webkit-details-marker { display: none }`）。
- 見出し全体（`<summary>`）が押せる範囲。高さは指で押しやすいよう `py-3` 程度。
- 困りごと同士の間は `border-b border-line` で区切る（今の `mb-8 mt-6` の余白は詰める。閉じた状態で一覧として読めるように）。

### 2. 開いた状態

- `<summary>` の下に、今と同じ制度カード（`serviceCardHTML`）と案内カード（`guideCardHTML`）を今と同じ順で出す。**カードの中身・見た目は変えない。**
- 複数の困りごとを同時に開いてよい（1つ開くと他が閉じる、はしない）。

### 3. 開閉の状態を保つ

- 開閉のたびに（`toggle` イベント）`state.openConcerns` を更新する。
- `renderConcern()` はプロフィールのタグを押すたびに一覧を描き直すため、描き直しのときに `state.openConcerns` に入っている
  困りごとには `open` を付ける（**タグを押したら全部閉じてしまう、を防ぐ**）。

### 4. 「すべて開く／すべて閉じる」

- `#concern-content` の先頭（最初のカテゴリ見出しの上）に、右寄せの小さなボタンを1つ置く。
  `text-xs text-bay font-medium`、枠なし。
- 1つでも閉じている困りごとがあれば「すべて開く」、全部開いていれば「すべて閉じる」と表示する。
- 押したら、表示中の困りごとをすべて開く（閉じる）。`state.openConcerns` も合わせる。

### 5. 共有リンク・全体像のリンクで開くとき

- 制度カードの共有リンク（`#base-…`）や、冒頭の「全体像」セクションのリンクで制度に移動するときは、
  **そのカードを含む `<details>` を開いてからスクロールする**（閉じたままだとカードが見えず、移動先が無いように見える）。
  - 対象は `scrollToBaseCard`（`handleHashRoute` から呼ばれる）。カード要素から `closest('details')` で親を探し、`open` を付け、
    `state.openConcerns` にも足す。
  - 同じ制度が複数の困りごとに出ている場合は、今と同じく最初に見つかったカード（`getElementById` の結果）の困りごとを開く。
    ほかの困りごとは開かない。
- 絞り込みの一時解除（共有リンクの設計書の仕様4）の動作は変えない。

### 6. 変えないもの

- カテゴリ見出しと件数、上部のジャンプナビ（カテゴリへの移動）、スクロールに合わせたジャンプナビの強調。
- プロフィールのタグによる絞り込みと、絞り込みで空になった困りごと・カテゴリを出さない動作。
- 冒頭の「全体像」セクション。

## 設計判断の理由（なぜこの設計にしたか）

### なぜ困りごと単位で閉じるか（カテゴリ単位・カード単位にしないか）

- **カテゴリ単位（4つ）**：1つ開くと9〜17件のカードが一度に出て、長さの問題がそのまま残る。
- **カード単位（45枚を名前だけにする）**：45行の一覧になり、困りごとという入口の意味が薄れる。
- **困りごと単位（20個）**：利用者が「自分の困りごと」を探して開く、というこのタブの考え方（2026-08-15）に合う。
  閉じた状態でも20個の見出しが1画面〜2画面に収まり、全体を見渡せる。

### なぜ制度名の1行を出すか

2026-08-15に「クリックしないと中身が見えない方式」をやめて常時展開にした経緯がある。
見出しだけにすると、何が入っているか分からないまま開いて確かめる手間が戻ってしまう。
制度名だけでも見えれば、開かずに「自分に関係ありそうか」を判断できる。

### なぜ開閉の状態を保存しないか

次に開いたときは別の困りごとを探していることが多く、前回開いたものが開いたままだと、かえって長くなる。
共有リンクで開いた場合も、その困りごとだけが開いていればよい。

### なぜ検索を入れないか

吉野さんの判断（2026-10-07）で折りたたみを選んだ。40件程度なら、見出しを見渡して開く方式で足りる。
なお、Chromeでは「ページ内検索」（Ctrl+F 等）で閉じた `<details>` の中の文字も見つかり、自動で開く。
Safari（iPhone）では閉じた中は検索で見つからない。件数がさらに増えたら、検索を別途検討する。

### 2026-10-07: 設計担当によるレビュー結果（Claude Code）

実装差分を設計書と突き合わせ、仕様1〜6のとおりであることを確認した。
jsdomで実HTML・実データを使ったシナリオテストを行い、すべて期待どおりだった。
- 初期表示：困りごと20個がすべて閉じていて、見出し・件数・制度名の1行がある
- 2つ開いた状態でプロフィールのタグを押し、戻しても開閉状態が保たれる
- すべて開く／閉じると、ボタンの文言の切り替え
- `#base-kikan-soudan-canvas` で「障がいのある子ども向けの支援」だけが開いてスクロールする。`#base-school-lunch-subsidy`、全体像のリンク、「妊娠中」での絞り込みの一時解除との組み合わせも同様
- コンソールエラーなし。ホーム画面に追加の既存テスト50項目も変わらず通過

**Claude Codeが直接修正した点（1点）**：開閉の印が記号の文字（`⌄` `⌃`）だった。サイトの書体（Zen Kaku Gothic New）に入っていない可能性が高く、
機種によっては「□」になるおそれがあるため、ほかの箇所と同じインラインSVGの矢印1つにし、開いたときにCSSで回転させる形にした。

設計書に無い追加：同じ制度へのリンクをもう一度押したとき（URLのハッシュが変わらず `hashchange` が起きない）にも
カードまで移動するよう、`a[href^="#base-"]` のクリックで `scrollToBaseCard` を呼ぶ処理が足されていた。既存の動作を壊さない改善のため、そのまま残す。
