# [2026-11-18] 「今日・開催中」のイベントを、その日だけのものから並べる 設計書

**設計者**: Claude Code
**実装担当**: Antigravity
**状態**: 実装完了・レビュー済み（push待ち）

## 概要

イベントタブの「今日・開催中」グループは、今は `events.json` の順（開始日が早い順）に並んでいる。
そのため、1か月続く教室や展示のような**期間の長いイベントが上に来て、今日しか行けないイベントが下に埋もれる**
（例：10/22〜11/19 のテニス教室が先頭に来る）。

運営者の要望（2026-11-18）により、「今日・開催中」グループだけ並び順を変え、**開催期間が短いものほど上**にする。
これで「今日だけ」のイベントが先頭に来る。

## データ構造

変更なし。`events.json` の既存項目だけを使う。

| 項目 | 使い方 |
|---|---|
| `start_date` | 開始日（`YYYY-MM-DD`） |
| `end_date` | 終了日。無ければ `start_date` と同じとみなす（今の画面と同じ扱い） |
| `time_text` | 時間の文字列（例：`19:00〜20:30`）。無いこともある |
| `title` | 最後の並べ替えに使う |

## 画面・API仕様

`renderEvents()` の中で `ongoing`（「今日・開催中」）を作ったあと、`groups.push` の前に `ongoing` だけを次の順で並べ替える。
**ほかのグループ（「1週間以内」・月ごと）と「申し込みの締切が近いイベント」の並び順は変えない。**

1. **開催期間の日数が短い順**
   日数は `end_date − start_date`（日単位の差）。その日だけのイベントは 0。
   日付は文字列 `YYYY-MM-DD` なので、`Date` に直して差を取る。タイムゾーンでずれないように、
   `new Date(str + 'T00:00:00')` 同士の差を `86400000` で割り、`Math.round` する。
2. 日数が同じなら、**開始時刻が早い順**
   `time_text` から最初に出てくる `時:分`（正規表現 `/(\d{1,2})[:：](\d{2})/`）を取り出し、分に直して比べる。
   時刻が読み取れないものは、時刻があるものの後ろに置く。
3. それも同じなら、**`title` の順**（`localeCompare(b, 'ja')`）

例（今日が 11/18 のとき）

| 並び | イベント | 期間 | 時刻 |
|---|---|---|---|
| 1 | 今日だけの講座A | 11/18 のみ（0日） | 10:00〜 |
| 2 | 今日だけのマルシェB | 11/18 のみ（0日） | 時刻なし |
| 3 | 2日間のお祭りC | 11/17〜11/18（1日） | 9:00〜 |
| 4 | 図書の特設コーナーD | 11/13〜11/29（16日） | 時刻なし |
| 5 | テニス教室E | 10/22〜11/19（28日） | 19:00〜 |

見た目（カードのデザイン・見出し「今日・開催中」）は変えない。並び順だけを変える。

## 設計判断の理由（なぜこの設計にしたか）

- **「その日だけ」と「それ以外」の2つに分けるのではなく、日数の短い順にする**：2日間・3日間のお祭りも、
  1か月続く教室より「今行かないと終わる」度合いが高い。日数で並べれば、それも自然に上に来る。
- **同じ日数なら時刻順**：その日だけのイベントが複数あるとき、朝のものから並ぶほうが一日の予定を立てやすい。
- **「今日・開催中」だけを変える**：「1週間以内」と月ごとのグループは、開始日の順に並んでいることに意味がある（いつ行けるかが分かる）。
- **`events.json` の順は変えない（画面側で並べ替える）**：カレンダー（.ics）作成など、ほかの処理に影響させないため。
