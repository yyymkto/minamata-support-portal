# [2026-11-18] お知らせを30件ずつ表示する 設計書

**設計者**: Claude Code
**実装担当**: Antigravity
**状態**: 実装完了・レビュー済み（push待ち）

## 概要

「最新のお知らせ」タブは、今は該当する記事（約330件）を一度に全部並べている。
そのためページがとても長くなり、古いスマホでは表示が重くなる。一番下の「このサイトについて」には、ほぼ誰も届かない
（2026-11-18 のデザインレビューの3点目）。

最初は30件だけ表示し、一覧の下に［さらに表示］ボタンを置いて、押すたびに30件ずつ足す。
**検索と絞り込みは、これまでどおり全件が対象。** 変わるのは「画面に並べる件数」だけ。

## データ構造

変更なし（`life_info.json` はそのまま）。

画面側の `state` に次の2つを足す。

```
state.feedFiltered: Array  // 今の検索・絞り込みに当てはまる記事（全件）。renderFeed() で作り直す
state.feedShown:   number  // 画面に並べている件数。初期値 FEED_PAGE_SIZE
```

定数 `FEED_PAGE_SIZE = 30` を、ほかの定数（`ENABLE_YOUNG_TAB` など）の近くに置く。

## 画面・API仕様

### 1. 最初の表示

```
328件の生活情報                       ← 件数は今までどおり「当てはまる全件数」
┌ カード 1 ┐
│   …      │
└ カード 30 ┘
┌──────────────────────────────┐
│     さらに表示（残り298件）     │   ← 横幅いっぱい、高さ h-12
└──────────────────────────────┘
```

- `renderFeed()` は、当てはまる記事を `state.feedFiltered` に入れ、先頭から `state.feedShown` 件だけカードにする。
- ［さらに表示］ボタンは `#list` のすぐ下に置く（`#empty` の前）。HTML に最初から置いておき、表示・非表示を切り替える。
  - 見た目：`w-full h-12 rounded-xl border border-bay text-bay bg-white font-medium text-sm`、上に `mt-4`。
  - 文言：「さらに表示（残り◯件）」。残りが30件未満のときも同じ文言（例：「さらに表示（残り8件）」）。
  - 全件を表示し終えたら隠す。当てはまる記事が0件のときも隠す。

### 2. ［さらに表示］を押したとき

- 次の30件（`feedShown` 〜 `feedShown + 30`）のカードを、`#list` の**末尾に足す**（`insertAdjacentHTML('beforeend', …)`）。
  一覧全体を作り直さない。作り直すと、スクロール位置がずれたり、表示済みのカードが入り直しの動き（`card-enter`）をしてしまう。
- 足したカードの `.open-detail` にだけクリック処理を付ける。`data-idx` は `state.feedFiltered` の中の通し番号にする
  （今と同じく `openModal(state.feedFiltered[idx])` で開けるように）。
- `state.feedShown` を増やし、ボタンの残り件数を書き換える（残りが0になったらボタンを隠す）。
- **キーボード・読み上げ対応**：足した最初のカードの `.open-detail` ボタンにフォーカスを移す（`focus({ preventScroll: true })`）。
  ボタンが隠れてフォーカスが行き場を失うのを防ぎ、続きから読めるようにするため。

### 3. 検索・絞り込みを変えたとき

- 検索語の入力、世代・ジャンルのチップを押したときは、`state.feedShown` を `FEED_PAGE_SIZE` に戻してから `renderFeed()` を呼ぶ。
  条件を変えたら、新しい結果の先頭30件から見せる。
- `renderFeed()` を呼んでいるのは、今は4か所（`src/index.html` の632行目付近：世代チップ、635行目付近：ジャンルチップ、
  710行目付近：検索欄、1991行目付近：初回表示）。ここで件数を戻す。
  ほかの場所から呼ばれている場合も同じく戻す（戻さずに呼ぶ必要がある場所は今は無い）。

### 4. 変えないこと

- 件数表示「◯件の生活情報」は、これまでどおり当てはまる全件数。
- カードの見た目、詳細画面（モーダル）、並び順。
- 画面復帰時の更新（30分以上たってデータが新しければ再読み込み）。再読み込み後は30件表示に戻るが、それでよい。

## 設計判断の理由（なぜこの設計にしたか）

- **ボタンで足す（下までスクロールしたら自動で足す方式にしない）**：自動で足す方式だと、一番下の「このサイトについて」や
  フッターにいつまでも届かない。どこまで読んだかも分かりにくい。高齢の方にも、押したら増えるボタンのほうが分かりやすい。
- **ページ番号で切り替える方式にしない**：番号で切り替えると、前のページの記事が画面から消える。お知らせは上から順に流し読みするものなので、
  下に足していく形が合う。
- **30件**：スマホで30件はおよそ画面15枚分。新着の流し読みには十分で、古いスマホでも重くならない。
- **全件をHTMLとしては並べ、見た目だけ省く方法（`content-visibility: auto`）にしない**：表示は軽くなるが、ページの長さは変わらず、
  「このサイトについて」に届かない問題が残る。
- **検索・絞り込みは全件が対象のまま**：30件だけを検索すると、探している記事が見つからない。
