# [2026-09-18] 制度カードの共有リンク 設計書

**設計者**: Claude Code
**実装担当**: Antigravity
**状態**: 実装完了（2026-09-18）

## 概要

制度カードごとに「共有」ボタンを付け、**その制度が表示された状態で開けるリンク**を
LINEなどで送れるようにする。

吉野さんとの相談（2026-09-17）で、希望者へのLINEプッシュ通知も検討したが、
配信アカウントの運用・費用・登録者情報の管理が継続的に発生するのに対し、
制度情報は「その人に必要になったときに読むもの」であるため、
**知っている人が必要な人にリンクを渡せる形**を先に作ることにした
（判断の詳細は「設計判断の理由」参照）。

現在、制度カードには `id="base-{base_id}"` が既にあるが、
**サイトを開くと必ず「最新のお知らせ」タブが表示される**ため
（[index.html:855](../../../src/index.html#L855)）、
`#base-school-lunch-subsidy` 付きのURLを送っても、受け取った人には
その制度が見えない。**この設計書の主眼は共有ボタンそのものより、
受け取ったリンクが正しく開くようにすること**にある。

## データ構造

**JSONの変更はしない。** 既存の `base_id` をそのまま共有URLの識別子として使う。

ただし次の制約が新しく生じる。

- `base_id` は `child_support_base.json` と `young_adult_support_base.json` の
  **両方を通じて一意**でなければならない（共有URLからどちらのタブの制度かを
  判定するため）。2026-09-18時点では重複なし（子育て39件・若者9件）。
  若者タブ側は `general-consultation-portal-ya` のように接尾辞で重複を避けている。
- `base_id` を変更・削除すると、**過去に共有されたリンクが開かなくなる**。
  変更が必要な場合は、リンク切れになることを承知の上で行う
  （下記「リンク先が見つからない場合」の扱いでエラーにはならない）。

## 画面仕様

対象は `src/index.html` のみ。トーン（`paper`/`ink`/`bay` の配色、明朝見出し）は変えない。

### 1. 共有ボタン（`serviceCardHTML` のみ）

`serviceCardHTML`（[index.html:566-613](../../../src/index.html#L566-L613)）の
カード下部、区切り線の下の帯に置く。現在この帯には「最終確認：YYYY-MM-DD」
（リンクなしカードでは出典も）が入っているので、**同じ行の右端**に小さく置く。

```
［費用の助成］ 小学生・中学生
学校給食費の全額補助
市内の小学校・中学校に在籍する児童生徒の…
─────────────────────────────
最終確認：2026-09-16                    [↗ 共有]
```

- ボタンは `text-[11px] text-inkSoft`、枠線なし、アイコン＋「共有」の語。
  **CTA（申請する）より視覚的に弱いこと。** 主役は制度への導線であって共有ではない。
- 帯は `flex items-center justify-between gap-2` にする。
  `last_verified` が無い項目でも共有ボタンだけは出す（帯自体は常に描画する）。
- リンクなしカード（`hasLink === false`）でも同じ位置に出す。
  出典の注記は現在の位置・文言のまま維持する。
- `guideCardHTML`（[index.html:615-625](../../../src/index.html#L615-L625)）には**付けない**。
  カード全体が `<a>` のため、中にボタンを入れると入れ子になる。理由は後述。

### 2. 共有の動作

```
[共有] を押す
  ├ navigator.share が使える（多くのスマホ）
  │   → OSの共有シートを開く（LINE・メール等はここから選ぶ）
  │     share({ title: "<制度名>｜みなまた くらしナビ（非公式）", url: <共有URL> })
  │     ユーザーがキャンセルした場合（AbortError）はエラー表示をしない
  └ 使えない（多くのPC）または失敗
      → クリップボードにコピーし、「リンクをコピーしました」を2秒表示
        → クリップボードも失敗した場合、URLを選択可能なテキストで表示する
```

- LINE等のSDKは読み込まない。**外部への通信を増やさない**（このサイトの方針）。
- `navigator.clipboard` は `https` か `localhost` でのみ使える。
  本番（GitHub Pages）は https なので問題ないが、`file://` で開くと失敗する。
  失敗時の表示まで実装すること。

### 3. 共有URLの形式

```
<今開いているURLからハッシュを除いたもの> + "#base-" + base_id
例: https://yyymkto.github.io/minamata-support-portal/#base-school-lunch-subsidy
```

- 既存のアンカー（`id="base-..."`）と同じ形式。全体像セクションの
  ページ内リンク（[index.html:759](../../../src/index.html#L759)）とも同じなので、
  新しい形式を増やさない。
- クエリパラメータは使わない。

### 4. 共有リンクを開いたときの動作（この設計書の主眼）

データ読み込み後に `location.hash` を見て、`#base-{id}` なら次を行う。

1. `state.baseById` と `state.yaBaseById` のどちらに属するIDかを判定する。
2. 対応するタブへ `switchTab('concern')` または `switchTab('young')`。
3. **子育てタブで、保存済みのプロフィール絞り込みによって対象カードが
   描画されない場合は、絞り込みを一時的に無視して描画する。**
   そのうえで、画面上部（`#concern-highlights` の直前）に一行の通知を出す。

   ```
   共有されたリンクを開いたため、絞り込みを解除して表示しています。［絞り込みに戻す］
   ```

   - **`localStorage` に保存されたプロフィールは書き換えない。** 表示だけを一時的に変える。
   - ［絞り込みに戻す］を押すと通常表示に戻り、通知も消える。
   - 利用者がプロフィールのタグを操作したときも、一時解除を終了して通常動作に戻す。
4. 対象要素へスクロールする（`scroll-mt-header` が既にあるので、
   ヘッダーに隠れない位置で止まる。仕様5・タスク9の実装を利用する）。
5. 該当する `base_id` がどちらにも無い場合（削除・改名された制度）は、
   **フィードタブのまま**にし、画面上部に一行だけ出す。

   ```
   お探しの制度は見つかりませんでした。一覧からお探しください。
   ```

   コンソールエラーを出さないこと。

**実装上の注意**

- **実行タイミング**：子育てタブのデータは `init()`、若者タブのデータは
  別の `initYoungAdult()`（[index.html:873](../../../src/index.html#L873)）で
  読み込まれる。**両方の読み込みが終わってから**この処理を実行すること。
  ただし若者データの読み込みに失敗しても、子育て分だけで判定して動くこと
  （2026-08-24の「1つの失敗で全タブが落ちる」事故を繰り返さない）。
- `hashchange` でも同じ処理を行う（同じページ内で別の共有リンクを踏んだ場合）。
- 全体像セクションの既存のページ内リンク（同じタブ内の `#base-...`）を壊さないこと。
- `history.pushState` などでURLを書き換える機能は**今回入れない**（理由は後述）。

### 5. LINEで送ったときの見え方（OGP）

`<head>` に次を追加する。現在 `<title>` と `description` はあるが
（[index.html:6-7](../../../src/index.html#L6-L7)）、OGPタグが無い。

```html
<meta property="og:type" content="website" />
<meta property="og:site_name" content="みなまた くらしナビ（非公式）" />
<meta property="og:title" content="みなまた くらしナビ｜世代別・生活情報まとめ" />
<meta property="og:description" content="水俣市公式サイトの新着情報を自動収集し、世代や立場ごとに整理する非公式ポータルです。" />
<meta property="og:url" content="https://yyymkto.github.io/minamata-support-portal/" />
<meta name="twitter:card" content="summary" />
```

- **制度ごとの見出し・説明にはできない。** このサイトは単一HTMLで、
  プレビューを出す側はJavaScriptを実行しないため、どの制度を共有しても
  同じ文言になる。制度ごとに出すにはページを制度の数だけ生成する
  （ビルドステップの導入）必要があり、今回のスコープ外とする。
- `og:image` は**用意しない**。画像を作ると別途管理が必要になるため。
  画像なしのテキストのみのプレビューになる。
- `og:url` はトップページ固定でよい（ハッシュはプレビューに影響しない）。
- **「非公式」の語をタイトル・サイト名から外さないこと。** 市の公式サイトと
  誤認されないため、2026-08-26の方針（`decisions-log/`）を引き継ぐ。

## 設計判断の理由

### なぜプッシュ通知ではなく共有リンクを先に作るか

2026-09-17に、希望者へのLINE通知を検討した。実現方法としては
「LINE公式アカウントを作り、GitHub Actionsから週1回まとめて一斉送信する」のが
最も軽く、実装自体は1日程度で済む。しかし次の負担が**継続的に**発生する。

- アカウントの運用（誰の名義で作るか、運用ポリシーの提示）
- 費用（無料枠は月200通。「送信回数×友だち数」で数えるため、
  週1回の配信なら友だち45人程度で上限に達し、以降は月5,000円のプランが必要）
- 配信内容の事前確認（新着情報の要約はAIが自動生成しており、
  サイトなら後から直せるが、送信済みのメッセージは取り消せない）

一方、制度情報は毎日変わるものではなく、「妊娠がわかった」「小学校に上がる」など
**その人に必要になった時に読むもの**である。継続的に押し出すより、
必要な人に渡せる形のほうが情報の性質に合う。共有リンクはサーバーも
登録者情報も不要で、上記の負担がいずれも発生しない。

なお市は既に公式LINE（`@minamata-city`）を運用しており、市からのお知らせ・
イベント・緊急情報を配信している。非公式サイトが並行して通知を送る場合、
市の配信との違いを利用者に説明できる必要がある点も、後回しにする理由になった。

### なぜ制度カード単位か（カテゴリ単位を入れないか）

2026-09-17の相談で吉野さんが「制度カードごと」を選んだ。
実際の使われ方も「この制度を教えたい」が中心と考えられ、
カテゴリ単位（「妊娠・出産」全体）を渡す場面は想像しにくい。
入口を増やすと共有ボタンが画面内に増え、主役である制度への導線が弱くなる。

### なぜ絞り込みを「一時解除」するのか

受け取った人が過去に「妊娠中」などのプロフィールを設定していると、
共有された制度が絞り込みで消え、**リンクが壊れているように見える**。
かといって相手の設定を勝手に書き換えるのは、本人が選んだ状態を
黙って変えることになる。そのため「表示だけ一時的に解除し、
解除していることを明示し、元に戻せる」形にした。

### なぜ `guideCardHTML` には共有ボタンを付けないか

案内カード（ガイドブック等）はカード全体が公式ページへの `<a>` になっている。
この中にボタンを置くと、`<a>` の中に `<button>` が入る構造になり、
押したときにどちらが反応するかが環境によって変わる。
カード構造を変えれば付けられるが、案内カードは「制度」ではなく読み物であり、
共有の必要性も低いため今回は見送る。必要になった時点で、
カード構造の変更とあわせて別途設計する。

### なぜURLの書き換え（`history.pushState`）を入れないか

タブを切り替えるたびにURLを書き換えれば、ブラウザの「戻る」でタブが戻り、
アドレスバーのURLをそのままコピーしても共有できる。ただし、
戻る操作・タブ・絞り込み・全体像のページ内リンクの組み合わせで
状態の整合を取る必要があり、今回の目的（送ったリンクが正しく開く）に対して
壊れやすさが見合わない。共有は明示的なボタンで行う。

### 制度ごとのプレビュー文言を諦めた理由

プレビューを生成する側はJavaScriptを実行しないため、
単一HTMLのままでは制度ごとの見出しを出せない。実現するには
制度の数だけHTMLを生成するビルドステップが必要になり、
「ビルドステップなし」という現在の構成
（`CLAUDE.md`／`AGENTS.md`に明記）を変えることになる。
共有の主目的は「開いたら目的の制度が見えること」であり、
プレビュー文言はそれに比べれば副次的と判断した。
