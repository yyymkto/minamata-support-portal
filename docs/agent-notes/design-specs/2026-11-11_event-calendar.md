## 概要

イベントタブに次の3つを足す。

1. **カレンダーの購読**：サイトのイベント一覧を、市民が自分のスマホのカレンダー（Googleカレンダー／iPhone・Macのカレンダー）に登録できるようにする。毎朝の更新が自動で届く。
2. **1件ずつの追加**：各イベントカードから、そのイベントだけを自分のカレンダーに入れられるようにする。
3. **カテゴリで絞り込む**：「マルシェ・物産」「スポーツ」などのボタンで一覧を絞り込む。

正本は今と同じ `public/data/events.json`（自動抽出・手動登録シート・投稿フォーム・広報みなまたの4経路）とする。
毎朝の処理で `events.json` からカレンダー形式のファイル（`.ics`）を作り、GitHub Pages で公開する。
Googleカレンダーは使わない（吉野さんの判断、2026-11-11。理由は「設計判断の理由」）。

一覧をリスト（カード）形式で見せる部分は、すでに実装済み（設計書 `2026-09-21_events-tab.md`）。今回は変えない。

## データ構造

### 1. `events.json` の各イベントに足す項目（`update_events.py` が出力）

```
{
  ...既存の項目はそのまま...,
  "category": "string (必須)",   // 下の「カテゴリ」表のキー。どれにも当たらなければ "other"
  "calendar": {                  // (必須) カレンダーに入れるときの日時。下の「日時の決め方」で決める
    "all_day": true | false,
    "start": "string",           // all_day=true なら "YYYY-MM-DD"、false なら "YYYY-MM-DDTHH:MM"（日本時間）
    "end": "string"              // all_day=true なら最終日の翌日 "YYYY-MM-DD"（iCalの決まり）、false なら "YYYY-MM-DDTHH:MM"
  }
}
```

- 画面（JS）は `category` と `calendar` を読むだけにする。判定の決まりはPython側の1か所だけに置く。
- 古い `events.json`（この2項目がない）が残っていても画面が壊れないこと（タスク5参照）。

### 2. カテゴリ

判定は新しいファイル `scripts/event_calendar.py` の `classify_category(event)` で行う。

| キー | 表示名 | 判定に使う言葉（初版。タスク2で調整する） |
|---|---|---|
| `market` | マルシェ・物産 | マルシェ, 物産, 漁師市, 朝市, 直売, 即売 |
| `kids` | 子育て・こども | 親子, 子育て, 育児, ママ, パパ, 未就学, 乳幼児, マタニティ, 妊婦, お誕生会, たまひよ, こども, 子ども, あそび, おはなし会 |
| `sports` | スポーツ | スポーツ, テニス, 野球, サッカー, ディスク, パドル, ボート, マラソン, ウォーキング, 歩き方, ヨガ |
| `festival` | お祭り・催し | 祭, まつり, フェスタ, フェスティバル, サミット, 感謝デー |
| `culture` | 文化・芸術 | コンサート, 公演, ライブ, 演奏, 展, 写真, 書道, 芸能, 合唱, 図書 |
| `learning` | 講座・体験 | 講座, 教室, セミナー, ワークショップ, 体験, 学習会, 勉強会, 作ろう, 会話 |
| `other` | その他 | （どれにも当たらないもの） |

判定の順番：

1. **タイトルの先頭が `【…】` の場合**：中の言葉が下の表に当たればそのカテゴリにする（手動登録・フォームで吉野さんがカテゴリを指定できるようにするため）。タイトルの文字は変えない。
   - `マルシェ`→market、`子育て`・`こども`→kids、`スポーツ`→sports、`祭り`・`お祭り`・`催し`→festival、`文化`・`芸術`→culture、`講座`・`体験`→learning
   - 先頭以外の `【…】`（例：`地域提案事業【一般社団法人…】`）は見ない。
2. **タイトル**を NFKC 正規化し、表の**上の行から順に**言葉を探す。最初に当たったカテゴリにする。
3. タイトルで決まらなければ、`summary` で2と同じことをする。
4. それでも決まらなければ `other`。

順番の意図：「物産祭」はマルシェ、「親子ヨガ」は子育て、「パドルフェスティバル」はスポーツ、「市民文化祭」はお祭りになる。

### 3. 日時の決め方（`calendar` 項目）

`scripts/event_calendar.py` の `calendar_slot(event)` で決める。

**(a) 時刻の読み取り**：`parse_times(time_text) -> (start, end)`（どちらも `"HH:MM"` または None）

- `time_text` を NFKC 正規化し、`H:MM` / `HH:MM` をすべて探す。
- 1つもなければ `(None, None)`。
- 先頭の時刻の直後が `〜` `~` `-` `－` のどれかで、すぐ次が2つ目の時刻なら、それを終了時刻とする。ただし：
  - 時刻が**3つ以上**ある（午前の部・午後の部など）→ 終了は None
  - 2つ目の前に `翌` がある、または終了が開始以前 → 終了は None
- それ以外は `(先頭の時刻, None)`。

| time_text | 結果 |
|---|---|
| `19:00〜20:30` | (19:00, 20:30) |
| `17:00〜` | (17:00, None) |
| `10:00` | (10:00, None) |
| `16:00開演（15:15開場）` | (16:00, None) |
| `①14:00〜 ②18:00〜` | (14:00, None) |
| `午前の部 10:00〜12:00、午後の部 14:00〜16:30` | (10:00, None) |
| `13:00〜翌10:00` | (13:00, None) |
| `8:50〜` | (08:50, None) |
| None・空文字 | (None, None) |

**(b) カレンダーの枠**

| 条件 | all_day | start | end |
|---|---|---|---|
| 1日だけ（start_date = end_date）で開始時刻あり・終了時刻あり | false | 日付T開始 | 日付T終了 |
| 1日だけで開始時刻あり・終了時刻なし | false | 日付T開始 | 開始の**1時間後**（日をまたぐなら23:59） |
| 1日だけで時刻なし | true | start_date | start_date の翌日 |
| 複数日で、期間が14日以内（end − start ≤ 13日） | true | start_date | end_date の翌日 |
| 複数日で、期間が15日以上 | true | start_date | start_date の翌日（初日だけ入れる） |

- 複数日のときは時刻を使わない（`9:00〜17:00（8日は16:00まで）` のように日ごとに違うため）。
- 15日以上の期間（例：10/22〜11/19 の全5回の教室）を帯で入れると「毎日開催」に見えるため、初日だけにする。その場合、カレンダーの件名の後ろに `（〜11/19）` を付ける（タスク3）。
- 終了時刻がないときの「1時間」は仮の長さ。説明文に元の `time_text` を必ず入れる（タスク3）。

### 4. 新しく公開するファイル（`scripts/build_calendar.py` が出力）

| パス | 中身 |
|---|---|
| `public/data/events.ics` | 全イベントを入れた購読用カレンダー |
| `public/data/ics/<id>.ics` | 1件ずつのカレンダー（カードの「iPhone・その他」用） |

サイトでのURL：`https://yyymkto.github.io/minamata-support-portal/data/events.ics`

## 画面・API仕様

### A. カレンダー購読の案内（`#events-content` の一番上、締切が近いイベントより前）

固定ヘッダーには入れない（スマホの画面を狭くしないため）。スクロールすると消えてよい。

```
┌───────────────────────────────┐
│ 📅 イベントをスマホのカレンダーで受け取る │
│ [ Googleカレンダーに追加 ]              │
│ [ iPhone・Macのカレンダーに追加 ]        │
│ 一度登録すると、新しいイベントは自動で   │
│ 追加されます。                           │
│ 毎朝更新します。アプリへの反映は数時間〜 │
│ 1日ほど遅れることがあります。やめるとき   │
│ はアプリの設定から削除できます。         │
└───────────────────────────────┘
```

- 「一度登録すると、新しいイベントは自動で追加されます。」は案内文の1行目に置き、太字にする（購読の価値を最初に伝えるため。吉野さんの依頼、2026-11-11）。
- カードの「📅 カレンダーに追加」（画面仕様C）を開いたところに、小さな注記「この1件だけを追加します。後から日時が変わっても自動では直りません。」を出す（購読との違いを分かるようにするため）。

- ボタン2つは縦並び（375px幅で折り返さない）。タップ領域は高さ44px以上。
- URLはページの場所から作る（ローカル確認でも動くように）：
  - `const icsUrl = new URL('./data/events.ics', location.href).href;`
  - iPhone・Mac：`icsUrl` の `https:`（または `http:`）を `webcal:` に置き換えたもの。`target` なしで開く。
  - Google：`https://calendar.google.com/calendar/r?cid=` + webcalのURL（**エンコードしない**。エンコードすると追加されない。2026-11-12 実機で確認）。別タブで開く（`rel="noopener noreferrer"`）。
- 定数 `EVENT_CALENDAR_ENABLED`（初期値 `true`）を作り、`false` ならこの案内とカードの追加リンクを出さない（不具合時にすぐ止めるため）。

### B. カテゴリの絞り込み（固定ヘッダーの一番下）

```
[すべて 66] [マルシェ・物産 5] [子育て・こども 9] [スポーツ 7] …  ← 横スクロール1行
```

- 並び：すべて → 表の順（market, kids, sports, festival, culture, learning）→ その他。**件数0のカテゴリは出さない。**
- 件数は「終了していないイベント」（今の `validEvents`）で数える。
- 選んだボタンは `aria-pressed="true"` と色で示す。初期は「すべて」。選択は保存しない（再読み込みで「すべて」に戻る）。
- 絞り込みは「締切が近いイベント」と各グループの両方に効く。中身が0件になったグループは見出しごと出さない。
- 全部0件になったら：`このカテゴリのイベントは今はありません。` と「すべて表示」ボタン。
- 購読（A）は絞り込みに関係なく全件のカレンダー。案内文はそのまま。
- 絞り込みボタンを足すとヘッダーの高さが変わるので、描画後に `scheduleHeaderOffsetUpdate()` を呼ぶ。
- `category` がないイベント（古い `events.json`）は `other` として扱う。

### C. イベントカードの変更

1. 日付の行の左にカテゴリのバッジ（表示名）を出す。`other` のときは出さない。
2. 「詳細を見る」リンクの横に、`<details>` で「📅 カレンダーに追加」を置く。開くと2つのリンク：
   - **Googleカレンダー**：`https://calendar.google.com/calendar/render?action=TEMPLATE` に次を付ける（別タブ）
     - `text`：タイトル（15日以上の期間なら後ろに `（〜M/D）`。タスク3と同じ）
     - `dates`：`all_day` なら `YYYYMMDD/YYYYMMDD`（start/end のハイフンを除く）、そうでなければ `YYYYMMDDTHHMM00/YYYYMMDDTHHMM00`
     - `ctz=Asia/Tokyo`
     - `location`：venue（あれば）
     - `details`：summary、`時間：{time_text}`、`詳細：{source_url}` を改行でつなぐ。500文字を超えたら切る
     - `calendar` がないイベントでは、このリンクを出さない
   - **iPhone・その他**：`./data/ics/<id>.ics`（`target` なし）
3. `<details>` の開閉に JS は使わない。

### タスク3の仕様（`build_calendar.py`）

- 入力は `public/data/events.json` だけ。Gemini・ネットワークは使わない（ローカルでそのまま動く）。
- 日時とカテゴリは `event_calendar.py` の関数で毎回計算する（`events.json` の `calendar` 項目には頼らない。`update_events.py` が失敗した日も作れるように）。
- カレンダー全体の項目：
  - `PRODID:-//minamata-support-portal//events//JA`、`VERSION:2.0`、`CALSCALE:GREGORIAN`、`METHOD:PUBLISH`
  - `X-WR-CALNAME:みなまた くらしナビ イベント（非公式）`、`X-WR-TIMEZONE:Asia/Tokyo`
  - `REFRESH-INTERVAL;VALUE=DURATION:PT12H`、`X-PUBLISHED-TTL:PT12H`
- 1件ごとの項目：
  - `UID:<id>@minamata-support-portal`
  - `DTSTAMP`：`events.json` の `last_updated` をUTCにしたもの（実行時刻は使わない。中身が同じなら出力も同じにするため）
  - 時刻あり：`DTSTART`・`DTEND` は日本時間から9時間引いたUTC（`...Z`）。VTIMEZONE は書かない
  - 終日：`DTSTART;VALUE=DATE:`・`DTEND;VALUE=DATE:`
  - `SUMMARY`：タイトル（15日以上の期間なら `（〜M/D）` を付ける）
  - `LOCATION`：venue（あれば）
  - `CATEGORIES`：カテゴリの表示名（`other` のときは書かない）
  - `URL`：source_url（あれば）
  - `DESCRIPTION`：次を改行でつなぐ（ないものは飛ばす）
    1. summary
    2. `時間：{time_text}`（時刻を使わなかった・終了時刻がなかった場合も必ず）
    3. `期間：M/D〜M/D（開催日は元のページでご確認ください）`（15日以上のときだけ）
    4. 申し込み：`要申込`／`一部要申込`／`申込不要` と、締切 `M/D締切`、`registration_note`
    5. `主催：{organizer}`
    6. `詳細：{source_url}`
    7. `みなまた くらしナビ（非公式）掲載。日時・内容は変わることがあります。`
- 書き方の決まり（RFC 5545）：改行はCRLF。値の中の `\` `;` `,` 改行はエスケープ（`\\` `\;` `\,` `\n`）。1行75バイトを超えたら、UTF-8の文字の途中で切らずに折り返す（次の行は半角スペースで始める）。
- `id` が `^[A-Za-z0-9_-]+$` に合わないイベントは、個別ファイルを作らずログに出す（購読用には入れる）。
- `public/data/ics/` の中で、今のイベントにない `.ics` は消す。
- 中身が前回と同じファイルは書き換えない。

## 設計判断の理由（なぜこの設計にしたか）

- **Googleカレンダーを正本にしない**：今の66件のうち45件は広報みなまた、19件はお知らせからの自動抽出で、Googleカレンダーには入っていない。カレンダーを正本にすると、これらを手で入れ直す二重管理になる。
- **ブラウザでGoogleの .ics や Calendar API を直接読まない**：Googleの公開 .ics はブラウザからの読み込み（CORS）を許しておらず、中継サーバーが要る。Calendar API はAPIキーをページに書くことになる。どちらも不要にするため、毎朝のGitHub Actionsで作ったファイルを置くだけにした。
- **購読の中身を「サイトの全イベント」にする**：Googleカレンダーの購読を案内すると、広報分などが届かない。自前の .ics ならサイトと同じ内容になる。
- **日時の決まりをPython側の1か所にまとめる**：.ics とGoogleの追加リンクで時刻がずれないようにするため。画面は `calendar` 項目を読むだけ。
- **カテゴリは言葉の表で決める（Geminiを使わない）**：毎回同じ結果になり、外れたときに表を直せば済む。タイトル先頭の `【…】` で手動指定もできる。
- **15日以上の期間は初日だけ**：全5回の教室などが、カレンダー上で毎日開催に見えるのを避けるため。
- **終わったイベントは購読から消える**：`events.json` が終了分を消すため。購読した人のカレンダーからも過去のイベントが消える。初版ではこのままにする（残すには別の記録ファイルが要る）。
