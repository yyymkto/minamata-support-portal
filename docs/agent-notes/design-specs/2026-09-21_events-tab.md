## 概要

水俣市内で開催予定のお祭り・マルシェ・スポーツ大会などを、開催日が近い順の一覧で見せる「イベント」タブを新設する。
想定利用者は水俣市民と、観光などで来る市外の人。
「一人暮らし・若者支援」タブは一時的に非表示にし、その位置にイベントタブを置く（コード・データは残し、フラグ1つで戻せるようにする）。

情報の入口は2つ。

1. **自動**：既存の自動収集（`life_info.json`）に入っているイベント記事から、Geminiで開催日・場所等を読み取る。
2. **手動**：Instagram（`@minamata_kanko_` 等）でしか告知されないイベントを、吉野さんがGoogleスプレッドシートに1行ずつ登録する（想定作業時間：週1時間以内）。

### 前提となる調査結果（2026-09-21時点）

- `life_info.json` 242件のうち、`topic_tags` に「イベント」を含むものが46件ある
  （湯の児マルシェ、市役所マルシェ、ハロウィンマルシェ、みなまた呑みの市、湯の児花火あそび、スポーツフェスタ等）。
  ただし `life_info.json` のスキーマには開催日・場所の項目がなく、要約も「詳細は公式サイトで」止まりのものが多い。
- 記事ページ本体には開催日・場所・時間が書かれている
  （例：`city.minamata.lg.jp/kiji0034775/` 湯の児花火あそび →「【日付】2026年10月3日（土）※雨天時10月4日へ順延【場所】湯の児海水浴場【開始時間】18時30分〜」）。
  go-minamata.jp の記事は本文の前にナビゲーションメニューの文字列が約600字入るが、本文自体は取得できる。
- SNS（Instagram等）の自動収集は、規約で禁止されていること・APIが使えないことから行わない（手動登録で補う）。

## データ構造

### `public/data/events.json`（新規・UIが読むファイル）

```
{
  "last_updated": "string (必須, ISO8601 JST)",
  "generated_by": "scripts/update_events.py",
  "items": [
    {
      "id": "string (必須)  自動: make_id(source_url) ／ 手動: 'm-' + sha1(イベント名+開始日+リンク)の先頭10桁",
      "title": "string (必須)",
      "start_date": "string (必須) YYYY-MM-DD",
      "end_date": "string (必須) YYYY-MM-DD。1日だけのイベントは start_date と同じ値",
      "time_text": "string | null  例: '18:30〜' '10:00〜15:00'",
      "venue": "string | null  例: '湯の児海水浴場'",
      "summary": "string | null  120字以内の紹介文",
      "organizer": "string | null",
      "source_url": "string | null  詳細ページ（元記事・Instagram投稿等）",
      "source_label": "string (必須)  リンクボタンに出す情報元名 例: 'みなまた観光物産協会' '水俣市' 'Instagram'",
      "origin": "'auto' | 'manual' (必須)"
    }
  ]
}
```

- `items` は `start_date` の昇順、同日なら `title` の昇順。
- 生成時点で `end_date` が今日（JST）より前のものは含めない。

### `public/data/_events_auto.json`（新規・内部用、UIからは参照しない）

自動抽出の結果のキャッシュ兼「判定済み」記録。同じ記事に何度もGeminiを呼ばないために使う。

```
{
  "entries": {
    "<source_url>": {
      "is_event": true | false,
      "checked_at": "ISO8601",
      "event": { events.json の item と同じ形（origin='auto'） } | null
    }
  }
}
```

- `life_info.json` に存在しなくなった `source_url` のエントリは、実行時に削除する。
- Gemini呼び出しが失敗した記事（429等）は記録せず、次回また判定する（`update_data.py` の `_checked_urls.json` と同じ方針）。

### `public/data/_events_manual.json`（新規・内部用、UIからは参照しない）

最後にスプレッドシートを読み込めたときの内容。CSVを取得できなかった日はこれを使う。

```
{
  "fetched_at": "ISO8601",
  "events": [ events.json の item と同じ形（origin='manual'。source_label は空欄なら null） ],
  "hidden_urls": [ "非表示行のリンク" ],
  "warnings": [ "3行目: 開始日を日付として読めません…" ]   // 読めなかった行。確認用
}
```

### Googleスプレッドシート（手動登録用）

1行目は見出し行。列の名前で読み込むので、列の順番は自由。

| 列名 | 必須 | 内容 |
|---|---|---|
| 非表示 | 任意 | 空欄なら掲載する。何か書いてある行（例：「x」）は掲載しない |
| イベント名 | 必須 | |
| 開始日 | 必須 | 日付形式（入力規則で日付のみ入力できるようにする） |
| 終了日 | 任意 | 空欄なら開始日と同じ |
| 時間 | 任意 | 自由記述（例：10:00〜15:00） |
| 場所 | 任意 | |
| 概要 | 任意 | 120字程度まで |
| 主催 | 任意 | |
| リンク | 任意（推奨） | Instagram投稿のURL等 |
| 情報元 | 任意 | リンクボタンに出す名前。空欄なら、リンクに `instagram.com` を含む場合は「Instagram」、それ以外は「詳細」 |

**自動抽出分の上書き・非表示**：スプレッドシートの行の「リンク」が自動抽出イベントの `source_url` と完全に一致する場合は、スプレッドシートの行を優先する。

- 「非表示」が空欄の場合：その行の内容で自動抽出分を置き換える（AIが日付を読み間違えたときの修正に使う）。
- 「非表示」に何か書いてある場合：その自動抽出イベントを掲載しない（イベントではない記事を誤って拾ったときに使う）。

スプレッドシートは「ファイル → 共有 → ウェブに公開 → 該当シート → カンマ区切り形式（.csv）」で公開し、そのURLをGitHubリポジトリの **Actions変数（Variables）** `EVENTS_SHEET_CSV_URL` に登録する。
コードにはURLを直接書かない（シートを作り直してもコード変更が不要になるように）。

## 処理仕様（`scripts/update_events.py`、新規）

`update_data.py` の後に、同じ `update-data` ジョブ内で実行する独立スクリプト。
`http_get`・`call_gemini_json`・`make_id` 等は `update_data.py` からimportして再利用する（`detect_stock_candidates.py` と同じやり方）。

1. **自動抽出**
   - 対象：`life_info.json` の項目のうち `topic_tags` に「イベント」を含み、`_events_auto.json` に未記録のもの。
     ただし市サイトのカテゴリ一覧ページ（URLが `/list数字.html` で終わるもの）は個別記事ではないので除く。
   - 記事ページを `http_get` で取得し、`<body>` の可視テキストを先頭から6000字まで切り出す。
   - Geminiに「タイトル＋本文＋今日の日付」を渡し、次のJSONを返させる。
     ```
     { "is_event": bool, "start_date": "YYYY-MM-DD"|null, "end_date": "YYYY-MM-DD"|null,
       "time_text": str|null, "venue": str|null, "summary": str|null, "organizer": str|null }
     ```
   - プロンプトで指示する判定基準：
     - `is_event=true`：水俣市内（または市が関わる近隣会場）で開かれ、一般の人が参加・観覧・来場できる催し（祭り、マルシェ、スポーツ大会・教室、花火、講演会、体験会等）。
     - `is_event=false`：出店者・出演者・ボランティア・デザイン案等の**募集告知**、開催結果の報告、テレビ放送の紹介、投票の呼びかけ、施設の開館状況。
     - 年が省略されている日付は、本文の文脈と今日の日付から補う。雨天順延の予備日は `end_date` に含めない。
     - 毎月開催など繰り返しのイベントは、本文に書かれている直近の開催日1回分だけを返す。
     - 日付が本文から特定できない場合は `start_date=null`。
     - 対象は「タイトルが示す催し」。本文でついでに触れている別の催しの日付は返さない。
       複数の催しを一覧で紹介する記事は `is_event=false`。ただし、1つの企画名で期間中に複数店舗・会場で
       行われるもの（まちゼミ、呑みの市等）は1つの催しとして企画全体の期間を返す。
   - Geminiが配列で返してきた場合は、まだ終わっていないもののうち開始日が最も早い1件を採用する。
   - 記事ページの取得失敗（削除済みページの404等）は、Gemini連続失敗の打ち切りカウントに含めない。
   - `is_event=true` かつ `start_date` がある場合だけ、イベントとして採用する。`end_date` が null なら `start_date` と同じにする。
     `source_label` は `life_info.json` の `source_name` から決める（「みなまた観光物産協会」で始まれば「みなまた観光物産協会」、それ以外は「水俣市」）。
   - 1回の実行でGeminiを呼ぶのは最大40件まで（`update_data.py` と同じくリクエスト間隔を空け、連続失敗時は打ち切る）。
2. **手動分の読み込み**
   - 環境変数 `EVENTS_SHEET_CSV_URL` のCSVを取得し、見出し名で読む（`csv.DictReader`、UTF-8）。
   - 日付は `YYYY/M/D` または `YYYY-MM-DD` を受け付ける。イベント名・開始日が欠けている行や日付を読めない行は、スキップしてログに警告を出す。
   - 環境変数が未設定の場合は手動分なしとして続行する。**CSVの取得に失敗した場合（見出し行に「イベント名」「開始日」が無い＝公開設定が外れてHTMLが返ってきた場合を含む）は、
     `_events_manual.json` に残っている前回分（非表示指定も含む）をそのまま使う**（一時的な失敗で手動登録分が消えないように）。
     ※当初は「前回の `events.json` の manual 項目を使う」としていたが、それだと非表示指定が失われ、
       非表示にした自動抽出分が一時的に復活するため、専用ファイルに変更した（2026-09-22、Claude Code）。
   - 終了日が読めない・開始日より前の場合は、開始日と同じ日として扱う。
   - 上書き行の「情報元」が空欄の場合は、上書き元の自動抽出イベントの `source_label` を引き継ぐ。
3. **統合・出力**
   - 自動分の重複をまとめる：開始日・終了日が同じで、空白・記号・「開催」等を除いたタイトルの一方が
     もう一方に含まれるものは同じイベントとみなし、項目が多く埋まっている方を残す
     （市サイトの `/kiji…/` と `/sports/kiji…/` の二重掲載や、市サイトと観光物産協会の両方で告知された催しへの対策）。
   - 自動分に手動分の上書き・非表示ルールを適用してから、手動分を足す。
   - 終了済み（`end_date` が今日より前）を除き、並べ替えて `events.json` に書き出す。
   - `items` の中身が前回と同じなら、ファイルを書き換えない（`last_updated` だけが変わる無意味なコミットを避けるため）。

### ワークフロー（`daily-update.yml`）の変更

- 「生活情報を収集・更新」の次に、ステップ「イベント情報を更新」（`python scripts/update_events.py`、`continue-on-error: true`、`GEMINI_API_KEY` と `EVENTS_SHEET_CSV_URL: ${{ vars.EVENTS_SHEET_CSV_URL }}` を渡す）を追加する。
- 「変更を検出」と「変更をコミット・push」の対象ファイルに `public/data/events.json`・`public/data/_events_auto.json`・`public/data/_events_manual.json` を追加する。
- イベント側の失敗ではIssueを起票しない（v1では、生活情報の収集が失敗したときだけ起票する今の動きを変えない）。
- スプレッドシートに書いた内容は翌朝7:00の自動更新で反映される。すぐに反映したいときは、GitHubのActions画面から手動実行（workflow_dispatch）する。

- `end_date < 今日` のものは表示しない（自動更新が数日止まった場合に備えて、UI側でも除外する）。
- 表示するイベントが0件の場合：「現在掲載しているイベントはありません。」
- ビューの一番下に小さく：「一部のイベントは、公開されている記事から日時・場所を自動で読み取っています。」
- v1では絞り込み・検索・共有ボタンは付けない。
- 色や余白は既存のカード（最新のお知らせのカード）に合わせる。375px幅で横スクロールが出ないこと。

## 設計判断の理由（なぜこの設計にしたか）

- **SNSを自動収集しない**：Instagram・Facebook・Xは規約で自動収集を禁止しており、APIも他人の投稿の検索には使えない（Xは有料）。手動登録で補う。
- **自動抽出は既存の収集データを入口にする**：イベント記事はすでに毎朝集まっている（46件）。足りないのは開催日・場所だけなので、新しい収集元を足すより、記事ページを読み直して項目を抜き出すほうが手間もリスクも小さい。`topic_tags` の「イベント」で候補を絞るので、Geminiの呼び出し回数も1日数件程度で済む。
- **`life_info.json` に項目を足さず、別ファイルにする**：お知らせとイベントでは寿命の考え方（公開日順／開催日順・終了したら消す）が違う。`update_data.py` の既存ロジック（`_checked_urls.json` による判定済み管理・並び順）に手を入れずに済む。
- **手動登録はGoogleスプレッドシート**：スマホからでも行を足すだけで済み、Gitやファイル編集が不要。入力規則で日付の書式ミスを防げる。上書き・非表示の行も同じシートで扱えるので、AIの読み取りミスを直す手段にもなる。
- **自動抽出分は確認なしで掲載する**（吉野さんの判断）：週1時間を手動登録に回すため。代わりに、注意書きと元ページへのリンクを必ず付け、日付を読み取れなかった記事は載せない。
- **若者タブは削除せずフラグでオフにする**：「一時的に」とのことなので、戻すときにデータ・コードを復元しなくて済むようにする。

### 既知の制限（v1では対応しない）

- 同じURLのまま内容が更新された記事（日程変更等）は、再判定しないので古い日付のまま残る（`update_data.py` と同じ制限）。スプレッドシートの上書き行で直す。
- Instagramとサイトの両方に同じイベントが出ている場合、手動登録すると二重に表示されうる。手動登録前にイベントタブを見て、既にあるものは登録しない運用で避ける。
- 画像の中にだけ日時が書かれた記事は読み取れない（掲載されない）。

## 運用（吉野さんの週1時間の使い方の目安）

1. イベントタブを開き、日付・場所がおかしいものがないか見る → あればスプレッドシートに上書き行か非表示行を足す（〜10分）。
2. `@minamata_kanko_` などのInstagramを見て、イベントタブに無いものをスプレッドシートに足す（残り時間）。

  呑みの市 9/29〜30 18:00〜、湯の児花火あそび 10/3 18:30〜 湯の児海水浴場、フライングディスク世界大会 2027/9/19〜24 エコパーク水俣 など。
  出店者募集・結果報告・テレビ紹介・投票の呼びかけ・「競り舟大会中止」は正しく対象外になった。
- 初回の試行で見つかり、上の処理仕様に反映した問題：
  (1) 本文でついでに触れている別の催しの日付を取る（世界大会の記事で今年の全日本大会の日付を取った）→プロンプトで対応。
  (2) 一覧ページがイベントとして拾われる→URLで除外。
  (3) 同じ催しが二重に出る→重複をまとめる処理を追加。
  (4) Geminiが配列で返す→1件を選ぶ処理を追加。
  (5) Geminiの503エラーで再試行せず打ち切られる→`update_data.py` の共通処理 `call_gemini_json` で、
      429に加えて500/502/503/504も再試行するよう変更（毎朝のお知らせ収集にも効く）。
- 残る割り切り：会場が「水俣市内」のように大まかになるものがある。Geminiの応答待ちがタイムアウト（20秒）した記事は、
  その回は判定されず次回に回る。
